# DeepDot 开发路线

## 已确认的方向

DeepDot 是对标 Grok Dot 交互方向的云端 Personal Agent，面向持续委托、随身感知、个人记忆和远程执行。沿用 deep-worker 的 Git 历史、npm workspaces、账户、权限和业务数据，逐项迁移 OpenDot 的相关能力。

- 品牌：`DeepDot`；包名：`deepdot`；M1 将原 GitHub 仓库重命名为 `Cordis798/DeepDot`。
- 执行：单 Agent 规划与执行；多用户、多会话和多设备保留，多 Agent Router、Subagent、Bot 协作在 M2 退出执行链路。
- 云端：优先 Workers + SQLite Durable Objects；Node 服务管理身份、凭据、权限、记忆与调度，云端调用通过授权网关进入设备或家居工具。
- 眼镜：先用手机/PWA 验证图像、语音和云端助手闭环，再适配有可用接口的真机；不预先承诺小米眼镜接口可用。
- 家居：首批交付 Home Assistant、米家官方 HA 桥接、涂鸦官方云 API 三类 Provider；机器人保留扩展位置。
- 图标：原创 Dot 标识，由一个 SVG 源生成各端资源，不沿用 OpenDot 机器人或照搬 Grok 图标。
- 节奏：每阶段小步提交、推送并提供 PR；验收后等待用户确认，再合并并进入下一阶段。

## 兼容边界

- 继续使用 deep-worker 自己的 SQLite 迁移序列，不导入 OpenDot 数据库或 schema 版本。
- 旧会话保留原运行时；新 Durable 会话固定执行位置，同一任务不能被 Node 与 DO 同时接管。
- Workers 不直接执行原生 SQLite、Docker、桌面控制和任意 stdio MCP；通过已授权 Node/设备节点调用。
- 配置迁移阶段增加 `DEEPDOT_*` 并兼容 `DEEP_WORKER_*`，新名称优先；M0 不修改配置协议。
- 执行预算只统计实际执行，审批等待单独统计；另设任务截止时间，避免无限等待。
- 单 Agent 可以分步骤调用工具；任务步骤和多个独立用户会话不等于多 Agent 协作。

## 公共契约方向

共享类型继续放在 `shared`，在对应阶段补充最小接口，而不是预先建立全套空实现。

| 契约                             | 职责                                    | 引入阶段   |
| -------------------------------- | --------------------------------------- | ---------- |
| Goal / Run                       | 目标、完成条件、步骤、预算、产物        | M5         |
| RequestIdentity / ToolCallIntent | 输入去重，调用参数、授权和回执绑定      | M4、M7     |
| DeviceCapability / WearableEvent | 设备声明、授权、音视频输入及会话关联    | M7、M11    |
| SmartHomeProvider                | 配置、发现、查询、控制、健康检查        | M10        |
| ExecutionEvent                   | 跨 Node、DO、Web 与 IM 的进度和错误投影 | M3–M5、M12 |

家居只提供一个统一 MCP 入口，在其下配置多个 Provider 实例。实体由实例与设备 ID 唯一标识，HA 与米家桥接中的同一物理设备显式关联，避免重复控制。
